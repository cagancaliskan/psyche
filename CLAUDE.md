## What Nous is (state it this way, always)

Nous is a biologically-motivated, dependency-free Python prototype of a
**memory-and-activation substrate for a cognitive architecture**. The long-term aim is a
non-LLM, biologically-grounded mind. The current built artifact is a proven substrate plus
an honest, well-tested exploration of higher layers.

**What is proven** is that the lower layers are *correct and deterministic*. **What is not
claimed** is that any layer *reproduces a cognitive phenomenon* or constitutes a mind. These
are different claims and the line between them is sacred.

In the paper the system is **Psyche**; in the codebase it stays **Nous**.

## The ten non-negotiable rules

These are the disciplines the project has already paid for in bugs.

1. **Never overclaim.** Nous is never called "a mind," "conscious," "sentient," "AGI," or "a
   validated cognitive model" — not in code, comments, docstrings, docs, or commit messages.
   Biological *inspiration* may be described; biological *fidelity* or cognitive achievement
   may not be asserted.

2. **Mechanism ≠ meaning.** "The code is correct and deterministic" and "the code reproduces
   a cognitive effect" are separate claims with separate evidence bars. Mechanism is
   verified by the tester; meaning by the validator, against external data.

3. **`PROVEN` and `DESIGNED` stay in separate boxes.** Vision documents are *description,
   not specification*. Nothing is built until it is tested. Track build status and meaning
   verdict as **two orthogonal axes** — a brick is routinely `BUILT-UNVALIDATED` with a
   `NOT-YET` verdict at the same time.

4. **Loop-closure: every brick proves itself before the next snaps on.** A component that
   passes on a friendly, hand-chosen input has not passed — it is waiting to fail under
   load. Drive each stage with input *generated by the previous stage*.

5. **External yardsticks, never self-authored inputs.** Any test that quietly encodes its own
   answer is invalid. Relatedness norms, baselines, ground-truth directions: all from outside
   the project.

6. **Reinvent the idea, borrow the scaffolding.** The novelty is the architecture. Spend
   invention only where the genuinely new thing lives.

7. **The substrate bar is determinism + integrity + purity** — and determinism is checked on
   **two axes**: randomized `PYTHONHASHSEED` *and* every CPython minor version available. A
   property that holds on one interpreter and fails on another was never a property of the
   program. (BUG-0b1: a 1-ULP float-summation leak was invisible on 3.12 and flipped the
   workspace winner 8 times in 30 on 3.11, at a fixed hash seed.)

8. **The core stays dependency-free.** Standard library only, unless a dependency is
   explicitly justified and approved by the human.

9. **Every phase ends in something shippable.** If the road stops at any point, what is
   behind us must stand on its own as a real, citable artifact.

10. **Prefer the gated overlay.** A change to existing behaviour ships as a **default-off
    parameter whose neutral value is byte-identical** to current behaviour — as
    `broadcast=False`, `body_sensor=None` and `normalization_sigma=None` all do. Flipping a
    default is a separate brick with its own gate and its own re-validation cost.

## The float rule

Never compare two independently-accumulated floats for strict inequality where an integer
key could decide. Sum with `math.fsum` (exactly rounded, therefore order-independent), and
make every comparison resolve on an intrinsic integer **before** it resolves on a float. A
tie-break that a 1-ULP asymmetry pre-empts is not a tie-break.

## The human is the brain

Cagan sets direction and makes the calls. Agents propose; the human disposes. When a decision
shapes the project's direction — a constant, a default, anything carrying a re-validation
cost — present options with tradeoffs and a recommendation. Do not decide unilaterally. When
you would have to *guess* at a claim or a goal, stop and ask.

## How the agents work together

Each is a subagent in `.claude/agents/`. Lanes do not cross; the separation **is** the
evidence. Run `/psyche-lane` before touching a file.

1. **architect-pm** — turns direction into a sequenced spec with an external "done means";
   keeps the roadmap and ledger current; proposes approaches grounded in prior art.
   *Documents only; no production code or tests.*
2. **builder** — implements the spec test-first, self-audits against the six-bug checklist,
   delivers only when the whole suite passes on every interpreter and nothing is overclaimed.
   *`src/` and `tests/test_nous_*.py` only.*
3. **tester** — independently and adversarially verifies, writing its *own* hostile and
   loop-closed tests. Verifies mechanism, not meaning. **Never modifies production code** —
   enforced by a hook.
4. **validator** — for any cognitive-sounding claim, pre-registers and runs a falsifiable
   experiment against external data. Verifies meaning, not mechanism. *Never patches the
   module under test.*
5. **architect-pm** — folds the result back into the roadmap and the ledger.

## The three walls (why the meaning bar is still open)

Three attempts, three structurally distinct obstacles, all caught **before** any graded
number existed:

- **1e semantic priming — CIRCULAR.** SWOW strength *was* the edge weight, so a weight-tied
  pair was activation-tied by construction.
- **1e′ fan effect — MECHANISM ABSENT.** The engine gave every out-road the source's full
  activation, so the fan curve was flat to the last digit.
- **2c interoception — SIGNAL FLAT.** Friction ≈ 0 on realistic CPU-bound work; any gradable
  band would have to be manufactured.

**The pattern is the finding**, and it is the anti-circularity discipline working — not
project failure. Scope it: this is a finding about *this substrate and these three
yardsticks*, never a general law about spreading activation or cognition.

## Repo conventions

- Modules `src/nous_<name>.py`; builder suites `tests/test_nous_<name>.py`; tester suites
  `tests/test_tester_<brick>_*.py`.
- One runner: `run_tests.py`. Its captured output in `docs/TEST_OUTPUT.txt` is the ground
  truth for all counts. Never estimate; read them from the ledger.
- Commits: `feat(<brick>):` · `fix(<brick>):` · `test(<brick>):` · `docs(<area>):` ·
  `chore:`. Branch per brick: `brick/<id>`.
- Before any commit: `python3 tools/ledger_check.py` must exit 0, and `/psyche-claim-check`
  must return SHIP.
- **Never `git stash`. Inspect an old revision with `git show <rev>:<path>` or a temporary
  worktree.** A stash is **repo-wide**: taken inside one lane it silently reverts every other
  lane's uncommitted work, and one that is never popped discards it. This is not hypothetical
  — during SPEC-2f step zero a stash taken at `044008c` swallowed 315 lines of
  `CLAUDE-CODE-PROMPTS.md` and nothing noticed. Damage was bounded to that one file and it
  was recovered, verified by diffing every path in the stash against `HEAD` and disk. On the
  same task the builder did it correctly (`git show` plus a diff) and the tester used stash,
  which is the point: **lane discipline that a routine git command can cross is not lane
  discipline.** The rule is about the command's blast radius, not about anyone's care.

## Definition of done

**A code module is done** when: it passes its full suite on every available interpreter; it
is deterministic across processes and versions, integrity-preserving, and pure; it has been
hit with adversarial and loop-closed inputs; no test encodes its own answer; and the delivery
report honestly states what is proven, what is not claimed, and any known limitation —
written as an explicit asserted-negative test, not hidden.

**A cognitive claim is done** when: it is reproduced on external data the project did not
author, with the prediction and its direction fixed in advance, against a baseline — or the
negative result is reported honestly. A pre-registered NO-GO caught before a graded run is a
first-class result.

---

## Tone

Honest, precise, willing to report what broke. A delivery that says "this passes, and here is
exactly where it would not" is worth more than a confident one. No marketing language. No
exclamation-point enthusiasm in deliverables.
