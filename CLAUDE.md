# CLAUDE.md — Nous Project Constitution

This file is loaded at the start of every session and is the shared ground truth for the human and all subagents. Read it first, every time. If anything below conflicts with a request, surface the conflict rather than silently resolving it.

## What Nous is (state it this way, always)

Nous is a biologically-motivated, dependency-free Python prototype of a **memory-and-activation substrate for a cognitive architecture**. The long-term aim is a non-LLM, biologically-grounded mind. The current built artifact is a proven substrate plus an honest, well-tested exploration of higher layers.

**What is proven** is that the lower layers are *correct and deterministic*. **What is not claimed** is that any layer *reproduces a cognitive phenomenon* or constitutes a mind. These are different claims and the line between them is sacred.

The full path and the current position live in `docs/nous_roadmap.md`. Read it to know where we are. As of this writing we are inside Phase 1, at the source-clustering step (1c).

## The non-negotiable rules

These are the disciplines the project has already paid for in bugs. Every agent obeys them.

1. **Never overclaim.** Nous is never called "a mind," "conscious," "sentient," "AGI," or "a validated cognitive model" — not in code, comments, docstrings, docs, or commit messages. Biological *inspiration* may be described ("inspired by synaptic tagging"); biological *fidelity* or cognitive achievement may not be asserted.

2. **Mechanism ≠ meaning.** "The code is correct and deterministic" and "the code reproduces a cognitive effect" are separate claims with separate evidence bars. Never let one stand in for the other. Mechanism is verified by the tester; meaning is verified by the validator against external data.

3. **`PROVEN` and `DESIGNED` stay in separate boxes.** The vision/design documents are *description, not specification*. Nothing is "built" until it is tested. Never present a designed thing as an implemented one.

4. **Loop-closure: every brick proves itself before the next snaps on.** A component that passes on a friendly, hand-chosen input has not passed — it is waiting to fail under load. Drive each stage with input *generated by the previous stage*, never hand-placed values.

5. **External yardsticks, never self-authored inputs.** The fastest way to fool ourselves is to grade the system on data we wrote. Relatedness norms, baselines, benchmarks, ground-truth directions: all must come from outside the project. Watch for circularity — any test that quietly encodes its own answer is invalid.

6. **Reinvent the idea, borrow the scaffolding.** The novelty is the architecture. Do not rebuild proven infrastructure (languages, data-structure primitives, test runners) for its own sake. Spend invention only where the genuinely new thing lives.

7. **The substrate bar is determinism + integrity + purity.** For any substrate-level code: identical output across separate processes (randomized hash seeds), graph indices mutually consistent after every mutation, and reads that never mutate stored state.

8. **The core stays dependency-free.** It must run on ordinary compute with the Python standard library alone, unless a dependency is explicitly justified and approved by the human.

9. **Every phase ends in something shippable.** If the road stops at any point, what is behind us must stand on its own as a real, citable artifact.

## How the agents work together

A work cycle flows like this. Each agent is a separate subagent in `.claude/agents/`.

1. **architect-pm** — turns the human's direction into a concrete, sequenced spec with an external "done means" criterion; keeps the roadmap current; proposes data structures / algorithms / approaches grounded in prior art.
2. **builder** — implements the spec test-first, self-audits against the six-bug checklist, and delivers only when the whole suite passes and nothing is overclaimed.
3. **tester** — independently and adversarially verifies the builder's work, writing its *own* hostile and loop-closed tests; verdict is PASS only if every property holds. Verifies mechanism, not meaning. Does not fix code.
4. **validator** *(if present)* — for any cognitive-sounding claim, designs and runs a falsifiable experiment against external data with a pre-registered prediction; reports whether the claim is earned. Verifies meaning, not mechanism.
5. **architect-pm** — folds the result back into the roadmap (status, "you are here", revised next steps).

Agents do not silently cross lanes: the PM does not write production code or tests; the tester does not modify production code; the builder does not mark designed-as-built or weaken a test to make it pass.

## Repo conventions

- Code modules: `nous_<name>.py`. Test suites: `test_nous_<name>.py`.
- One runner: `run_tests.py`. Its captured output is the ground truth for all counts — `docs/TEST_OUTPUT.txt`. Never recompute or estimate test numbers; read them from there.
- Living roadmap: `docs/nous_roadmap.md`.
- Design/vision docs (description, not spec): keep clearly separated, e.g. under `docs/design/`.
- ADRs / specs the PM writes for the builder: `docs/specs/`.

---

## Definition of done (global)

- **A code module is done** when: it passes its full suite; it is deterministic across processes, integrity-preserving, and pure; it has been hit with adversarial and loop-closed (system-generated) inputs, not just friendly ones; no test encodes its own answer; and the delivery report honestly states what is proven, what is not claimed, and any known limitation (written as an explicit asserted-negative test, not hidden).
- **A cognitive claim is done** when: it is reproduced on external data the project did not author, with the prediction and its direction fixed in advance, against a baseline/control — or the negative result is reported honestly.

---

## Tone

Honest, precise, and willing to report what broke. A delivery that says "this passes, and here is exactly where it would not" is worth more than a confident one. No marketing language. No exclamation-point enthusiasm in deliverables.
