## 2. THE RESOLVED SIGNED DIRECTION (Step 1 — fixed before any graded number)

This is the load-bearing pre-registration item. It is resolved **from the engine code, not the spec prose**, and
reconciled with principled prior art. **Where the spec prose and the engine's true semantics disagree, the
principled direction is pre-registered against the engine's REAL semantics, and the disagreement is surfaced, not
silently resolved.**

### 2.1 The engine's ACTUAL semantics (read from `src/nous_activation.py`, not the spec)

The single transmission line in `spread_activation` (`src/nous_activation.py`, line 259) is:

```
transmitted = outgoing * road.strength * decay_per_hop
```

with `decay_per_hop ∈ (0, 1]` and a locality `floor` below which activation is not propagated (line 260:
`if transmitted < floor: continue`). Therefore, **in this engine `decay_per_hop` is a per-hop TRANSMISSION
MULTIPLIER, not a "penalty":**

- A **HIGHER** `decay_per_hop` → **more** activation survives each hop → activation reaches **FARTHER** before
  dropping below `floor` → spread is **MORE BROAD / more diffuse** (far, sprawling coalitions are relatively
  favored).
- A **LOWER** `decay_per_hop` → **less** activation survives each hop → activation drops below `floor` **sooner**
  → spread is **MORE LOCAL / tighter** (near, tightly-bound coalitions are relatively favored).

This is verifiable by arithmetic alone (no run): for fixed `outgoing` and `road.strength`, `transmitted` is
strictly increasing in `decay_per_hop`, and the number of hops surviving the `floor` is non-decreasing in
`decay_per_hop`. **The builder documented this exact semantics in `src/nous_bodysensor.py` (lines 145–156),
flagging that SPEC-2c's prose labels `decay_per_hop` the opposite way ("higher decay → more local").** That prose
label is **wrong about the engine**; the engine's real behavior is *higher decay → more broad.*

### 2.2 The principled direction (prior art — verified, not fabricated)

What *should* high friction / high system load do to cognition? The established principle is **attentional
narrowing under arousal**:

- **Easterbrook, J. A. (1959). "The effect of emotion on cue utilization and the organization of behavior,"
  *Psychological Review* 66(3), 183–201 — the cue-utilization hypothesis.** *Verified (WebSearch, 2026-06-21:
  the paper, author, journal, and the core claim all confirmed across multiple independent sources, incl. the
  Frontiers 2014 "Redefining the Easterbrook hypothesis" review.)* *Establishes (in human cognition, not Nous):*
  as physiological/emotional **arousal increases, the range of cues utilized NARROWS** — attention is
  increasingly allocated to a smaller set of central, dominant cues, with peripheral information progressively
  excluded ("tunnel vision" at the extreme). It built on Yerkes–Dodson by giving the narrowing an attentional
  mechanism.

The analogue, stated narrowly and with no overclaim: a telemetry-derived **friction/load** scalar is the
mechanistic *shadow* of an arousal/load state, and the principled prediction is that **higher load NARROWS the
spread of activation toward near, tightly-bound structure** — the cognitive-narrowing direction. (This is an
analogy of *direction*, not a claim that Nous has arousal, emotion, or attention. Easterbrook describes humans;
Nous tests only whether a load scalar moves its emergent selection in the narrowing direction.) Corroborating
lineage already cited in SPEC-2c: Damasio's somatic-marker hypothesis (a bodily state biases which option is
selected) and the neuromodulatory-gain framing (a global gain/decay change, not a targeted command).

### 2.3 The pre-registered signed direction (mapped through the REAL engine semantics)

Combining §2.1 (engine truth) and §2.2 (principled direction), the frozen signed direction is:

> **PRE-REGISTERED DIRECTION (FROZEN):**
> **higher friction B → LOWER `decay_per_hop` → MORE LOCAL spread → near, tightly-bound coalitions favored over
> far, diffuse ones.**

Concretely, as B rises across the realistic range, winner identity is predicted to shift **toward the
tighter/nearer coalition** (the one whose members sit closer, in graph-distance, to the perceived sources), and
**away** from the broader/more-distal coalition. The directional readout (§7) is the **sign** of how winner
identity moves with B: a flip from a broader winner (low B) to a tighter/nearer winner (high B) is **in the
pre-registered direction**; the reverse is a **direction reversal** (falsifier, §10).

### 2.4 Does the IMPLEMENTATION match the principled direction? (YES — no sign fix needed)

**The implementation already maps higher friction → lower `decay_per_hop`.** From `src/nous_bodysensor.py`:

```
friction_to_decay_factor(friction) = 1 - MODULATION_SPAN * friction      # monotone DECREASING in friction
modulated_decay_per_hop(base, friction) = base * (1 - MODULATION_SPAN * friction)   # MODULATION_SPAN = 0.6
```

So as friction rises from 0 → 1, the factor falls from 1.0 → 0.4, i.e. `decay_per_hop` is scaled **down** →
**more local** spread (per §2.1). This is **exactly** the principled narrowing direction of §2.2/§2.3.
**Therefore the implementation MATCHES the principled, pre-registered direction; no sign fix is required, and
nothing is routed back to the builder on this point.**

> **The honest disagreement, surfaced (not silently resolved):** SPEC-2c's *prose* (§4 / decision 2) describes
> the chain as "higher friction → **higher** decay → more local," which is internally inconsistent: in the real
> engine higher decay → **more broad** (§2.1). The builder followed the spec's cognitively-stated **intent**
> ("higher friction → stays more local → near coalitions favored"), not its mislabeled mechanism, and
> implemented higher-friction → **lower**-decay → more-local. **That intent IS the genuine hypothesis** (it is
> the Easterbrook-narrowing direction), and the implementation realizes it correctly against the engine's true
> semantics. This pre-registration adopts the **principled / intent** direction (higher friction → lower decay →
> more local), which the implementation already satisfies. The spec *prose* should be corrected to match the
> engine (a documentation fix for the architect-pm), but **no mechanism change is needed** and the graded run is
> **not** grading a wired-in wrong sign.

## 5. THE REALISTIC PERCEPT DESIGN (distinct from the pilot's contested-by-design battery; fixed NOW)

This is the first of the two pre-registration items the roadmap flagged as open. It must be a principled,
fixed-seed **realistic-percept distribution** that does **NOT** pre-select for flip-capability, and it must be
**demonstrably DISTINCT** from the pilot's contrived-to-flip battery.

### 5.1 Why the pilot battery is contrived-to-flip (the thing this must NOT do)

The pilot (`experiments/pilot_2c_populability.py`, `build_battery`) constructs, for **every** percept, a single
**CONTESTED NODE** (`midnode`) placed at **deliberately asymmetric distances** from the two anchors: 1 medium hop
from `alpha` (strength set by `bridge_n` traversals) and 2 strong hops from `gamma` (`gnode → midnode`, 30
traversals). The pilot's own docstring states this sets a **crossover** `d* = sA / sB²` and **spreads `d*` across
~[0.18 .. 0.60]** via `bridge_n ∈ [1..6]`, so — verbatim from the pilot — **"Every percept is therefore movable
IN PRINCIPLE."** The pilot deliberately engineers a basin-allegiance crossover into each topology so that the
*populability* question ("does the real telemetry range reach each percept's built-in crossover") is clean. That
is exactly the right design **for a feasibility pilot** and exactly the **wrong** design for a meaning run: it
**pre-selects for flip-capability by construction.** A realistic meaning run must measure flips on percepts that
were **not** built to flip.

### 5.2 The realistic battery — principled, fixed-seed, NOT pre-selected to flip (FROZEN)

The realistic battery is generated by a **fixed-seed random generator** over a **documented realistic
parameter space**, producing small multi-domain topologies that resemble what the closed loop actually perceives
(perception lights up nodes whose content matches input tokens; the field spreads from clustered source
representatives; coalitions form by basin; one wins). **No contested node is engineered, and no crossover is
positioned.** Concretely (all parameters fixed here, before any number):

- **Seed:** **`BATTERY_SEED_REALISTIC = 20260622`** — **distinct** from the pilot's `BATTERY_SEED = 20260621`
  (so it is an **independent draw**, not the pilot set re-labelled), and distinct from EXP-1e's `20260621` and
  EXP-1c's `20260620`. The generator is fully deterministic given this seed (sorted construction, seeded
  `random.Random`).
- **Battery size:** **`PERCEPT_COUNT_REALISTIC = 60`** two-anchor percepts (larger than the pilot's 40, so the
  realistic flip-rate is estimated on more probes; ≥ 30 is the minimum for a powered proportion, mirroring the
  EXP-1e `N ≥ 30` convention).
- **Topology family (realistic, NOT contrived-to-flip):** each percept names **two anchors** drawn from a fixed
  vocabulary of non-substring-overlapping content words (so perception lights up exactly the two anchors, as in
  the pilot — this keeps perception clean, it does **not** engineer a flip). Around each anchor, a **small
  multi-node neighborhood** is grown with **randomly drawn, independently sampled** structural parameters:
  - **`domain_size`** ∈ **[2..5]** per anchor (number of near neighbors of that anchor), drawn **independently**
    for the two anchors (so the two domains are **generically asymmetric in size**, as realistic domains are —
    but the asymmetry is random, not tuned to cross a basin).
  - **`internal_n`** ∈ **[8..30]** traversal count for each anchor→neighbor road (the domain's internal
    cohesion), drawn **independently per road** (so cohesion varies realistically across roads).
  - **`bridge_present`** ∈ **{True, False}** with **p = 0.5**, and if present, a **single** cross-domain bridge
    `anchorA → (a random neighbor of anchorB)` with **`bridge_n`** ∈ **[1..30]** traversal count drawn
    **uniformly and independently** of everything else. Crucially, **`bridge_n` is NOT constrained to position a
    crossover** — it is a free uniform draw over the full [1..30] range, so a bridge may be weak, medium, or as
    strong as internal cohesion, **at random**. There is **no** `midnode`, **no** asymmetric-distance contested
    node, and **no** computed `d*` — the topology is grown from independent random structural draws, and whether
    any given percept's winner moves under the realistic friction range is an **honest, unbiased measurement**,
    not a built-in property.
  - **`depth_extra`** ∈ **[0..1]**: with `depth_extra = 1`, one anchor gets a **second-hop tail** (a neighbor of
    a neighbor) so some percepts have genuine distance-2 structure that a `decay_per_hop` change can reach or not
    — again drawn at random, not positioned to flip.

The parameter space is documented and **fixed before any capture or run**; randomized generation over it means
the battery is **not hand-picked for flippability.** The fraction of realistic percepts whose winner moves across
the realistic friction range is therefore an **honest measure of whether realistic telemetry meaningfully moves
realistic selection** — which is exactly the meaning question (SPEC-2c §2), **not** the pilot's
populability-on-contrived-inputs question.

### 5.3 Concrete distinctness from the pilot (documented, per the directive)

| Property | Pilot battery (`build_battery`, contrived-to-flip) | Realistic battery (this §5, honest) |
|---|---|---|
| Seed | `20260621` | **`20260622`** (independent draw) |
| Count | 40 | **60** |
| Contested node | **YES** — a `midnode` engineered at asymmetric distances (1 medium hop from alpha, 2 strong hops from gamma) | **NO** — no contested node, no `midnode`; neighborhoods grown from independent random draws |

The realistic battery is therefore **provably not** the pilot battery and **does not** pre-select for

### 6.1 The realistic workload — provenance CORRECTED (Decision 1, 2026-06-21) and the HONEST-FALLBACK caveat (Decision 2)

> **PROVENANCE CORRECTION (Decision 1; mandatory, applied regardless of Decision 2).** An earlier draft of this
> section described the band as *"friction values that arise from real contention during real work (GC, allocation,
> OS scheduling, the yield), spanning a moderate, continuous band."* **On the tester's measured evidence that
> description is FALSE and is retracted.** When the as-written capture (`think()` per interval + a fixed
> `time.sleep(REALISTIC_YIELD_S = 0.5 ms)`) was measured, the friction band came out **[0.79 .. 0.93], mean ≈ 0.86,
> and is YIELD-DOMINATED — it does NOT track real machine contention.** The reason is exact arithmetic, not
> opinion: `friction = 1 − cpu_dt/wall_dt` is a **stall fraction** that only rises when the process is **off-CPU**;
> `think()` alone is ≈ 47 µs of CPU work and is essentially **CPU-bound** (`wall ≈ cpu ⇒ friction ≈ 0`); the fixed
> 0.5 ms `sleep` is ≈ 10× the work and is the **only off-CPU interval**, so it occupies ≈ 91% of every interval and
> **sets the band's level** (`1 − 47/(47+500) ≈ 0.914`, matching the observed mean). The band's *level* therefore
> reflects the **yield-to-work ratio**, and its *width* reflects `think()`-timing jitter around that
> sleep-pinned floor — **neither is a real-machine-contention signal.** A graded result over this band must **NOT**
> be reported as tracking machine contention it does not actually track; it is, accurately, **a yield-influenced
> friction signal, not a contention-tracking one.**

**The capture as originally written** ran a **representative mixed cognitive workload** — repeatedly run `think()`
(the real cognitive cycle) on a rotating set of short utterances over a small fixed workload substrate, with a
brief `time.sleep(REALISTIC_YIELD_S)` between intervals — and read the timing pair at each boundary. The fixed
capture parameters were `CAPTURE_SAMPLES_REALISTIC = 300`, `REALISTIC_YIELD_S = 0.0005` (0.5 ms),
`SWEEP_LEVELS_REALISTIC = 9`, and a fixed `WORK_UTTERANCES` rotation over a workload substrate **separate from the
§5 percept battery** (the trace must not be co-constructed with the battery). That capture **mechanically runs and
serializes a trace**; what it does **not** do — established now, by reasoning, before any graded number — is
produce a **contention-tracking** friction band. The corrected provenance above is the accurate description of
what that trace's friction signal is.

**Why a contention-tracking band is NOT reachable on this workload without manufacturing waits (the reasoning

### 6.1.1 BAND DESIGN DECISION (Decision 2, 2026-06-21): HONEST FALLBACK — real contention-driven variation is NOT achievable on this workload without manufacturing waits

**The decision the human required between (revise toward genuine contention-driven width) and (honest fallback) is
resolved by the physics of the signal. The decision is: HONEST FALLBACK — the timing-pair friction signal does not
vary meaningfully from real machine contention on a realistic Nous workload, and that is recorded as the honest
finding.** The full reasoning, fixed before any graded number:

**(1) `friction` only moves when the process is OFF-CPU.** By definition `friction = clamp(1 − cpu_dt/wall_dt, 0, 1)`
(`src/nous_bodysensor.py`, `compute_friction`). It is a **stall fraction**: it is ≈ 0 whenever the process runs
flat-out (`wall ≈ cpu`) and rises toward 1 **only** as the process spends a larger fraction of the wall interval
**waiting off-CPU**. Nothing else can raise it.

**(2) A realistic Nous `think()` workload is CPU-bound and generates almost no off-CPU waits.** `think()` is
single-threaded, in-memory, pure compute with **no I/O and no blocking**. The off-CPU events available to such a
process are: (i) **GC pauses** — but CPython's cyclic collector runs **in-thread** and is counted as
`process_time` CPU, so a GC pass makes `think()` *slower* while keeping `wall ≈ cpu` and **does not raise
friction**; (ii) **allocation** — the arena/free-list fast path is CPU; only a **first-touch page fault** is a
brief off-CPU stall, and those are tens of microseconds and sporadic; (iii) **paging/swap** — only under genuine
memory pressure (RSS near physical RAM), which a KB-scale substrate never approaches; (iv) **OS preemption** — rare
and brief for a CPU-bound process holding its core on an unloaded machine; (v) **I/O / lock waits** — `think()`
performs none. So a realistic Nous cycle produces essentially **no** off-CPU waits, and friction sits at ≈ 0 with
negligible real variation.

**(3) Making the workload *heavier* does not help — friction is a ratio, scale-invariant in work magnitude.** A
pure-CPU interval has `friction ≈ 0` whether it is 10 µs or 100 ms, because `cpu/wall ≈ 1` regardless of size.
Varying `think()`'s size moves **duration**, not the **cpu/wall ratio**, so a bigger/heavier graph operation does
**not** widen the friction band. (Arithmetic check, no run needed: for pure-CPU work of any magnitude `W`,
`1 − W/W = 0`.) The only lever on friction is the **off-CPU fraction**, which heavier compute does not increase.

**(4) Therefore the only way to obtain a wide friction band on this workload is to MANUFACTURE off-CPU waits** —
the injected `sleep` (what the as-written capture does, yielding the yield-dominated `[0.79..0.93]` band, §6.1),
**or** GB-scale allocations to force swapping, **or** saturating every core with rival processes to force
preemption. **All of these are manufactured contention, not real Nous-workload contention** — they are the pilot's
deliberately-extreme busy-spin-vs-sleep error in a new costume, and they are **explicitly forbidden** by the
anti-manufacture guard (do **not** widen the band with artificial sleeps/allocations/hand-tuned delays; the
variation must come from real compute contention, of which this workload has ~none).

**(5) The interpretability consequence (the human's Decision-2 reasoning, adopted).** A narrow, yield-dominated
band makes the test **asymmetrically uninterpretable**: a NOT-YET could not separate *"telemetry does not couple"*
from *"friction barely varied from contention, so modulation could not be seen even if it existed"*; and an EARNED
would be the strange claim that *a near-constant, sleep-pinned variable moved selection.* The test needs enough
**real** contention-driven variation that either outcome is interpretable — and §6.1.1(1)–(4) prove that variation
is **not honestly obtainable** on this workload. Hence the fallback.

> **THE RECORDED HONEST FINDING (pre-registered, fixed here):** *On a realistic Nous `think()` workload, the

## 13. Why the closed loop is required (not the bare engine)

The bare engine could show "a lower `decay_per_hop` makes activation more local" — trivially true and a
**pass-through** (a parameter doing what parameters do). The claim becomes meaningful **only through the closed
loop**, because only the loop has the **emergent competition (1d-i `select_winner`)** that turns a diffuse global
parameter change into a **categorical winner-identity change** distinguishable from a readback, and the
**broadcast (1d-ii)** that lets a body state leave a trace across cycles. 2c is therefore a **Phase-1-loop result
wearing a Phase-2 label**: it tests the *built, tester-verified* loop (1c/1d) against a *real, external,
non-circular* yardstick (live telemetry), with the direction fixed from external prior art (Easterbrook 1959).

## 14. Prior art (the direction and the control logic — NOT evidence Nous reproduces cognition)

- **Easterbrook, J. A. (1959). "The effect of emotion on cue utilization and the organization of behavior,"
  *Psychological Review* 66(3), 183–201.** The cue-utilization hypothesis: higher arousal **narrows** the range
  of cues utilized (central/dominant cues favored, peripheral excluded). *Verified (WebSearch, 2026-06-21).*
  *Establishes the human DIRECTION* (higher load/arousal → narrower selection). *Nous tests* only the analogous
  emergent-selection direction under a telemetry-derived load scalar — **not** arousal, **not** attention, **not**
  emotion.
- **Damasio, A. (1994). *Descartes' Error*; the somatic-marker hypothesis.** A bodily state biases which option
  is selected. *The 2c analogue, narrowly:* a telemetry-derived body-state variable biases **which coalition wins
  the workspace** — the mechanistic shadow of a somatic marker, with **no** claim of somatic feeling.
- **Candia-Rivera, D. (2026). "Interoceptive machine framework," *Cognitive Systems Research* (arXiv:2604.24527).**
  Distinguishes **interoceptive variables that influence control dynamics** from **passive telemetry that does
  not** — the conceptual basis for the §11 pass-through guard. *Verified (WebSearch, 2026-06-21).* Borrowed only
  for the **control-coupling** criterion.
- **Yerkes, R. M. & Dodson, J. D. (1908).** The arousal–performance inverted-U that Easterbrook's narrowing
  mechanism refines. Cited as lineage for *why* a load variable would shape processing — **not** as evidence Nous
  has arousal.

**The honest separation, stated once:** the literature establishes that *in humans* higher arousal/load narrows
the range of cues utilized. 2c tests only whether *Nous's emergent selection, under a telemetry-derived load
scalar injected as a global spreading gain, moves in that narrowing direction on realistic inputs, reproducibly,
distinguishably from a pass-through and from baseline churn.* A match is *"the direction is reproduced against a
real, external machine signal,"* **never** *"Nous feels its body"* and **never** *"Nous is aware."*
